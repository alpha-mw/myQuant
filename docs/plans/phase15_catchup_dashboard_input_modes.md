## Architect revision: concrete implementation contract

- The input profile requires BOTH the top-level role and exact path from the two incident refs above. Nonmatching role paths retain strict `raw` (preserving existing owner-only arbitrary Dashboard refs); directly invoking the dedicated input method with a mismatch rejects with `CATCHUP_DASHBOARD_INPUT_ROLE_PATH_INVALID`. Wrong/swapped/duplicate roles cannot gain 0644 permission. No arbitrary path receives the relaxed profile.
- `check_template_sources(source, validated_recipe, *, profile="FRESH")` takes the original full validated template. Only code chooses `FROZEN_REGISTERED_RECOVERY`, and only for v6; it skips `store_preimages` and the benchmark role, while still reading risk-free. No dictionary deletion or inferred profile. Check recognized schema and exact top-level field set before selecting roles. Versions v4/v5/v6 gain the two exact input roles. Existing supported v1/v2/v3 templates retain a strict recursive walk, with their existing exact schema shape; they gain no input-profile permission. This compatibility detail preserves the existing public catch-up contract.
- New private `_source_bytes.py` extracts the existing descriptor-relative preparation algorithm. Explicit arguments are `allowed_modes`, `maximum_bytes`, `require_owner`, `require_single_link`, `require_non_executable`. Preparation uses 0400/0600/0644 and 8 MiB; Dashboard catch-up uses the same modes and 32 MiB. All three boolean requirements are true at both callers. `BindingSources.raw/document` remain on the unchanged owner-only System reader, 32 MiB.
- Shared helper checks canonical ASCII relative path, System directory traversal/casefold policy, current UID, regular file, single link, no execute or group/world write, owner read, nonempty bounded size, `O_NOFOLLOW|O_NONBLOCK`, and before/after/named-entry full stat identity (device, inode, mode, UID, GID, link count, size, mtime_ns, ctime_ns). No file mutations or fallback. Unsafe metadata/path conditions raise `SystemSecurityError`; ordinary I/O raises `SystemStorageError` (retaining the OS cause). A private drift exception maps to the caller's existing changed code. This explicitly normalizes preparation's former mixed internal `CommandError`/`PreparationError`/OS security failures to System security errors; preparation SHA and changed codes remain unchanged. Test exact classes and codes.
- Dedicated `BindingSources.dashboard_input(role, ref)` records per-path profile, role, expected ref, bytes, full identity and maximum. `recheck()` uses the same enrolled profile and checks identity plus bytes. Strict use always calls the existing strict reader independently; input-profile enrollment cannot satisfy it. Bad expected SHA raises `CATCHUP_BINDING_SOURCE_SHA_MISMATCH`; valid-policy identity/byte/profile drift raises `CATCHUP_BINDING_SOURCE_CHANGED`. Unsafe drift still raises the underlying security error, never a retry.
- Cover automatic fresh/frozen resolution, launcher `_producer_controls`, and `run_upstream_catchup` fresh preflight. The latter two explicitly select FRESH. CSV parsing remains in native consumers. No public schema or authority change.
