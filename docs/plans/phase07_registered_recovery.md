# Registered daily recovery: original execution custody

Status: Architect and Critic APPROVE with the exact amendments below.
Origin custody, committed-package metadata recovery and automatic cross-day
routing are implemented and locally validated. Whole-path installed/native and
unattended acceptance remain open.

Implemented checkpoint: automatic-origin.v1 publication and immutable readback,
active capability/lease binding, controller forwarding through a distinct private
CURRENT argument, handoff v4 publication/replay, cutoff source custody and
completed/archived snapshot transport. Direct CURRENT remains v2 and historical
remains v3. Original resolution replay for registered v6 no longer reopens the
mutable Store/Event/benchmark heads or benchmark CSV; fresh execution and launcher
producer classification still require those exact live preimages.

The committed-DAG inspector now proves original request/retained recipe,
handoff2/4, cutoff2, materialization6/native7 and native C1 plan/commit before any
recovery write. Configured origin additionally replays the exact preparation
objects, source capture/plan and linked REQUEST_AVAILABLE locator history. Native
source file modes and native C1 JSON encoding are preserved; cutoff physical
read timestamps retain their fractional precision. The existing metadata owner
samples its actual observation before either write and calls a private guard
under strategy/day/Store locks. Changed custody, native identity or time blocks
both pointer-copy and completion writes. Existing complete metadata is replayed
without timestamp replacement. EXECUTE and RESUME use this guard after a changed
registered writer; restricted direct EXECUTE also routes to it. The original
native input then resumes through the existing EOD runner.

Launcher inspection v3 now selects NONE, SERVING_ONLY or COMMITTED_DAG_RECOVERY.
Automatic ACTIVE recovery checks original registered commit/package before the
expired-unstarted branch, then dispatches the existing catchup controller with
the private committed restriction. This route performs no fresh template-head
preflight, binding/origin creation or source/cutoff acquisition. The native
recovery owner still rechecks the package under its locks before writes.

After native EOD replay, exact serving expiry yields AUTO_PUBLICATION_EXPIRED
with sorted completed_eod_refs. Original binding/origin, completed range and
publication expiry replay again before matching ACTIVE becomes IDLE. The same
error remains nonzero on repeat with unchanged bytes. Foreign requests cannot
skip the older registered publication proof. Unknown/source/replay errors retain
ACTIVE. A serving-only restriction cannot upgrade itself to DAG recovery.

Expired-unstarted proof retains native maintenance and day exclusion. Its exact
preparatory allow-set now includes binding v3, original origin-only execution
inputs and the source preparer's validated commitment/generated objects/capture/
plan/request markers. Unknown files, other execution/config roots, a maintenance
handoff, node evidence or native claim still block closure. No producer budget
or financial authority is granted by that exception.

The final EOD runner, real Core/Factor/install admission and full automatic
configured chain remain explicit seams in local recovery tests. Automatic
coordinator/CLI tests use real registered source custody and storage but control
commit-package/EOD admission and publication observation; the preceding native
package test separately exercises actual synthetic C1 CAS interruption/recovery.
264 related tests passed. No installed or unattended proof is claimed.

Source/preparation Calendar and maintenance/Core Calendar are distinct captures.
`source_slot_inputs.capture_calendar` owns the first, while maintenance handoff
binds `checkpoint.close_session_receipt_ref` and its original raw Calendar.
`store_materialization_arguments` uses the latter for native Store planning.
Their bytes and observation times must not be declared interchangeable merely
because their target day agrees. The earlier C2 requirement equating the source
locator Calendar SHA directly to the native plan SHA is not valid for this path.

Normal registered Store CAS follows maintenance handoff, cutoff v2, materialization
v6 and native input v7. Therefore recovery after CAS can require that complete
original execution package. It never needs to sample a new cutoff or run source
producers merely to reconstruct missing post-CAS completion metadata.

Proposed recovery checks:

1. Read only the exact original execution request and its matching retained
   request/recipe, maintenance handoff and cutoff v2 at code-owned paths.
2. Replay the registered declaration and native frozen plan-v2/final commit.
   Require original plan time <= cutoff physical/portfolio/seal times <= CAS
   observation time. Same declaration and baseline/writer/final identities must
   match throughout.
3. Replay the handoff's original Core Calendar/raw pair and require its receipt
   SHA equal the native Store plan Calendar preimage. Market/benchmark/Event/
   policy preimages and previous-EOD Store baseline must match exactly.
4. Configured source recovery additionally verifies the original REQUEST_AVAILABLE
   locator -> preparation commitment -> source request/template chain, including
   config/date/declaration and prepared_at <= native plan time. Replay its own
   original source Calendar/raw and prove request/derived-execution identity;
   retain both Calendar roles rather than equating their bytes.
5. Existing EOD goes directly through its complete native replay. Without EOD,
   resume the existing cutoff/native input and native nodes, never another
   financial CAS, provider acquisition or cutoff creation. Missing execution
   custody blocks the dependent recovery with a typed code. A standalone C1
   finalization cannot be enrolled afterwards.
6. Launcher inspection classifies a fully verified retained recovery as local
   repair so it does not request provider credentials. Ordinary unstarted work
   retains its existing producer classification and admission checks.

The decisions below resolve original-source transport and direct EXECUTE scope.
Do not add a new mutable index or search by SHA/path suffix. Preserve existing
release/lease/lock and public command boundaries.

Acceptance: configured source -> automatic launcher -> retained execution recovery
on the original and later dates; zero provider/cutoff/CAS calls, exact old bytes

## Accepted architecture decisions

Direct EXECUTE recovery is rooted in the original execution package and does not
add a configured source locator requirement. Require original retained request/
recipe, handoff, cutoff2 and materialization6/native7 before resuming. All source
identities and times are replayed; no new cutoff or provider call is permitted.
Where native C1 CAS metadata is missing, use only its existing proven-commit
metadata-recovery owner, never a financial writer. Do not fabricate an original
CAS timestamp: the recovered `cas_observed_at` remains an actual observation.
The original input package must already exist before any such metadata repair.

Automatic origin is obtained only through a private accessor on the existing
active `automatic_execution` capability, which rechecks its lock, fingerprint,
pending lease and exact resolution. It returns auto_request_ref, resolution_ref
and derived_request_ref. The controller adds the exact catchup binding/execution
refs and target day and seals `inputs/automatic-origin.v1.json` in that execution:

```
schema_version auto_request_ref resolution_ref derived_request_ref
catchup_binding_ref execution_request_ref trade_date authority
```

The artifact reader replays the complete forward chain and exact v6 declaration,
previous completion and writer preimage. It neither searches by SHA nor changes
the public request schema. An independent private current-origin argument keeps
the existing historical `_catchup_binding_ref` interpretation unchanged.

Handoff version matrix: direct/ordinary CURRENT retains v2; registered CURRENT
entered through automatic capability uses v4 = exact v2 fields plus non-null
automatic_origin_ref; historical v3 stays unchanged. Existing physical handoff
filename is retained. The origin must be created under the valid capability;
replay uses the immutable artifact, not a still-live ContextVar. v2/v3 forbid the
v4 field. Cutoff2 validates origin transitively through handoff and source refs.

Only a matching ACTIVE request/resolution can take committed recovery before
the existing expiry-unstarted branch. Full original package proof preserves
ACTIVE and resumes the original derived execution. A started but unproven case
stays ACTIVE with typed recovery-unconfirmed error. Foreign ACTIVE requests never
borrow this proof. Completely unstarted expiration retains its existing native
absence proof and immutable closure.

Registered automatic launcher inspection uses v3, existing fields plus exact
recovery_scope = NONE, SERVING_ONLY or COMMITTED_DAG_RECOVERY. Ordinary existing
inspection profiles retain their previous meaning. The committed scope selects
the private committed_recovery_only restriction, not the existing no_producers
mode that only permits completed EODs. Inspection is revalidated at execution.

Existing serving expiry rejection remains intact. It cannot prevent recovery
of an already-started EOD with pre-CAS inputs, but final output must still disclose
an expired required publication and exit nonzero. If that exact expiry error is
raised after all EODs independently replay complete, the matching ACTIVE lease
may become IDLE under its lock so the next day is not blocked forever. Do not
write EXPIRED_UNSTARTED closure, extend validity or change completed evidence.
Unknown/financial/source/replay errors cannot use this exception to retire lease.

Configured origin additionally validates its original REQUEST_AVAILABLE source
locator, preparation commitment, auto request and resolution. Source Calendar
binds that construction; Core Calendar binds native Store plan. Each is replayed
independently to the same target day, without equating its bytes to the other.

## Final Critic scope and error contract

Standalone C1 `recover_close_completion` keeps its existing financial metadata
semantics. It cannot manufacture a request, handoff, cutoff, materialization or
EOD. The new registered DAG recovery caller must validate the complete original
package again under the day, Store and automatic locks before using that owner.
Missing or changed package evidence allows zero metadata writes through this
DAG path. Its scope binds workspace, day, execution request, recipe6, handoff2/4,
cutoff2, materialization6, native7, Store plan2 and final pointer; automatic
execution additionally binds the original artifact and matching ACTIVE lease.

Before the first committed-pointer or completion write, check native proof and
the original package, then sample trusted current UTC. Require the maximum of
original custody times <= sampled cas_observed_at <= trusted current UTC. An
existing completion retains its original bytes and timestamp; a recovered one
records the actual recovery observation, never an inferred original CAS time.

If publication has expired after all required EODs replay complete, emit typed
`AUTO_PUBLICATION_EXPIRED` with `completed_eod_refs`: sorted exact
`{trade_date, completion_ref}` rows covering every required day after the anchor.
Each row must replay natively and use its fixed completion path. Under the same
automatic lock recheck the origin, matching ACTIVE and complete set, write/read
back IDLE, then raise the error and exit nonzero. Extend AutomaticCatchupError
and its CLI wire validator for this field. Do not introduce a success schema or
put completion refs in PARTIAL rows of production-result.v1.
