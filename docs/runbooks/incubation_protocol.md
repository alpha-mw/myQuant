# v13 冻结与孵化协议

## 1. 冻结对象

- 冻结版本：`v13-frozen-20260707`
- 策略对象：`CN/aggressive_tech_manufacturing`
- 起始条件：Phase 12 的 12.1-12.3 提交、验收命令与本协议提交完成；`maxwell` 已于 2026-07-08 填写第 4 节数值阈值。本协议按冻结 tag 日 `2026-07-07` 生效。
- 冻结期：90 个交易日，以 A 股交易日历为准。
- 周度追踪时间：每周五 17:30 CST。

## 2. 冻结期代码规则

冻结期内唯一允许的代码变更是 bug 修复。每次例外必须满足：

1. 通过 PR 提交，不直接绕过代码审查。
2. PR 必须打 `freeze-exception` 标签。
3. PR 描述必须说明 bug、影响面、为何不改变策略主张、验证命令与结果。
4. 不允许引入新 alpha、风险偏好放宽、参数主动优化、数据口径替换、择时规则重写或人工事后调参。
5. `results/strategy_records/`、`results/track_record_audit/`、benchmark CSV、审计报告/JSON/PNG 继续不得 commit。
6. 例外审批口径：`测试绿 + Codex review`。当前不启用 GitHub branch protection / required checks，由本协议和本地验收命令约束执行。

## 3. 周度预登记追踪指标

每周收盘后固定复跑 Phase 12 审计结构，至少记录：

1. 对科创50 `star50_nav` 的周超额收益。
2. 滑点漂移：按买/卖方向统计提案价 vs 实际成交价 bps 均值、中位数、P90。
3. 周换手率与滚动 4 周换手率。
4. 出场后 5/10/20 日收益滚动均值与中位数。
5. Markov regime 触发次数、`ThemeGatePolicy.from_markov` 档位变化次数、相位闸门触发次数。
6. 单票权重超过 `RISK_GUARD_SINGLE_NAME_WEIGHT_CAP` 的存量提示数量与最大超限幅度。
7. 相位择时 alpha、组内选股 alpha、配置 beta 的滚动对账。
8. 对科创50 `star50_nav` 的回归 beta、年化 alpha、alpha t 值与 R²。
9. 信息比率 IR（日频，同时留存年化换算）。
10. 暴露合规率：实际总暴露 ≤ Markov/系统建议总暴露上限的天数占比。
11. 选择 alpha：实际所选标的收益 − 当日 shortlist 菜单等权收益。
12. 毛/净双口径全窗口收益与周度成本拖累估计。
13. 两条影子账本差值：`shadow_nav_cap050` vs actual、`shadow_nav_machine_exit` vs actual。
14. 决策日志完整率：`advisory` 与 `human_action` 有同日配对记录的比例。

## 4. Kill / 加仓规则

以下阈值为 `maxwell` 的预登记风险偏好输入，已于 2026-07-08 填写。本节生效后，90 个交易日冻结期评估只能按这些事先规则打分，不允许事后重写解释口径。

- 回撤 kill：若组合峰值回撤达到 `-20%`，目标暴露减半；若达到 `-40%`，进入逐票人工确认清仓复盘。代码不得因该规则自动强制卖出，只能输出风险清理建议与执行证据。
- 资金 kill：若连续 `4` 周对科创50周超额低于 `0%`，进入冻结期复核/停止新增资金；动作口径为转人工复核后可执行。
- 相位 kill：若滚动 `60` 日相位择时 alpha 低于 `-5%`，停止机器日频调仓主张；机器仍可给减风险卖出建议。
- 执行 kill：若买入或卖出方向滑点 P90 超过 `50` bps，且持续 `2` 周，则冻结新增交易；人工 override 后仍可买卖。
- 出场 kill：若出场后 10/20 日收益滚动均值显著为正并超过 `30%`，则判定卖出偏早，暂停相位出场规则扩展。
- 加仓评估：若连续 `4` 周对科创50周超额高于 `5%`，且相位择时 alpha 高于 `5%`，可进入小额加仓评估；单次加仓不超过 NAV `10%`。
- Markov/相位评估：若 Markov/相位闸门在回撤期触发并使最大回撤低于科创50至少 `5pct`，可评估提高资金上限。
- 存量超限：单票超过 `RISK_GUARD_SINGLE_NAME_WEIGHT_CAP` 的既有持仓继续只提示当前权重、上限和建议减持路径，不强制卖出。
- 资金性质：冻结期记录按混合口径管理，逐笔标注资金性质与成交来源。
- 决策日志：`Codex` 仅在 `maxwell` 确认后记录人工动作；`advisory` 与 `human_action` 需要同日配对。
- Phase 5b/9b：冻结后再议，冻结期内不作为加仓或策略改写理由。

## 6. 期满评估模板

期满后按 Phase 12.2 报告结构复跑并对比冻结起点：

1. A 基础绩效：累计收益、年化波动、最大回撤、Calmar、Sharpe、周换手、持仓期、逐笔命中率与盈亏比。
2. B 基准与超额：科创50为主考官，同时列 `chinext_nav`、`csi300_nav`、`industry_ew_nav`。
3. C 三分解：配置 beta、组内选股 alpha、相位择时 alpha 与总超额对账。
4. D 集中度与稳健性：Top3 贡献占比与剔除 Top3 后收益。
5. E 对手盘验证：入场/出场后 5/10/20 日收益分布。
6. F 执行质量：滑点、门禁拒单、总成本拖累。
7. G 归因切分：版本切段、人工 vs 系统、资金性质。

若全窗口超额 vs 科创50 ≤ 0 且相位择时 alpha ≤ 0，复评结论必须沿用 Phase 12 预登记失败规则。
